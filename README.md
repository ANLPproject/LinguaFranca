# LinguaFranca

> **"Do Internal Failures Predict External Ones?"**  
> Causal Hop Localization for Faithful, Efficient Retrieval-Augmented Multi-Hop QA

---

## Overview

This repository implements the full data and modelling pipeline for the project. We test whether a lightweight probe on an LLM's hidden states can detect and localize a failing reasoning hop **at the hop boundary** — before subsequent steps are generated — and whether that signal is **causally** responsible for the failure (via activation patching).

### Five Phases
| Phase | Description | Location |
|---|---|---|
| 1 | **Data construction & hop labeling** | `phase1_dataset/` |
| 2 | **Internal-state probing** | `advanced_probing.py`, `src/pipeline/probes.py` |
| 3 | **Causal validation (activation patching)** | `create_kaggle_phase4_patching.ipynb` |
| 4 | **Naive Restart RAG intervention** | `src/pipeline/` (see below) |
| 5 | **Evaluation vs Doctor-RAG baseline** | `src/pipeline/evaluate.py` |

## Phase 1 — Dataset Construction

### What Happened
In Phase 1, we built the dataset required to train a probe that detects reasoning failures in LLMs based on their hidden states.

### Why Did We Do This?
Large Language Models usually answer questions correctly, meaning natural failures are rare. To train a balanced probe, we need both successful reasoning paths and failed ones, along with the model's internal "brain activity" (hidden states) during both.

### How Was It Done?
1. **Generated Reasoning**: Fed multi-hop questions to the model to generate Chain-of-Thought reasoning.
2. **Recorded States**: Saved the model's internal hidden states while it generated its reasoning.
3. **Labeled Hops**: Programmatically graded each reasoning hop as Success or Failure based on whether it retrieved the correct bridging entity.
4. **Counterfactuals**: Artificially induced failures by swapping entities in the prompt, forcing the model to fail, which balances our dataset.
5. **Split Data**: Separated the data into train, val, and test splits securely.

### What Should We Do Next?
**Phase 2 — Internal-state probing**: We will train a classifier probe on `train.jsonl` using the hidden states saved in `data/hidden_states/` to predict hop-level failures before they fully manifest in text.

## Phases 3–5 — Probe-triggered Naive Restart vs. Doctor-RAG-style judge

Code: `src/pipeline/` · Kaggle notebook: `kaggle/pipeline_phase3_5.ipynb` (generated by `scripts/make_pipeline_notebook.py`).

### What it does
1. **Live probing** (`generation.py`). Greedy token-by-token decoding with `model.forward()` + KV cache. When `</hop1>` or `</hop2>` closes, the hop's hidden states are mean-pooled exactly as in Phase 1 and scored by the hop-specific probe (hop 1 and hop 2 probes both at layer 10; the 28-layer CV sweep is reported for RQ4).
2. **Interrupt → retrieve → Naive Restart.** If P(fail) ≥ τ (τ maximises F0.5 on out-of-fold train predictions), generation stops. The question plus the failing hop's text queries a FAISS index (all-MiniLM-L6-v2) over pooled 2Wiki + HotpotQA paragraphs. The top-3 passages not already in context are prepended, the cache is flushed, and generation restarts.
3. **Baseline** (`judge.py`). Doctor-RAG-style: generate the full trajectory, then the same 3B model judges hop 1 and hop 2 (the team's judge prompt, logit P(fail)). The same retrieval and restart run from the earliest flagged hop.
4. **Evaluation** (`evaluate.py`) compares five systems: no intervention, probe trigger, judge trigger, always-retrieve, and an oracle trigger. It reports detection P/R/F0.5/AUROC, first-failure localization, detection earliness, end-to-end EM/F1, fixed vs broken answers, paired-bootstrap CIs, token cost, wall-clock latency, accuracy-vs-cost sweeps and the RQ4 layer table. Datasets: the 2Wiki held-out test split and HotpotQA (OOD).

Greedy decoding makes a halted trajectory an exact prefix of the uninterrupted one. So every trajectory is generated once with the probe in monitor mode, the restarts are pre-computed, and all systems and thresholds are evaluated from the cache. A 100-question subset runs truly live, to verify this and to measure latency.

### Settings
| `--setting` | first-stage context | data on HF |
|---|---|---|
| `tfidf` (main) | TF-IDF top-5 of the 10 2Wiki passages (gold often missing) | `tfidf_distractor_rag/` (branch `experiment/distractor-rag`) |
